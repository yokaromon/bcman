# Person/Company aggregation is scoped to Sharing Mode, not Organization-wide

Directory could have aggregated Person and Company across an entire Organization regardless of Group boundaries, maximizing dedup accuracy. Instead, merge candidates are only ever drawn from the Confirmed Contacts a User can already see under their Organization's Sharing Mode (see [Identity](../../identity/CONTEXT.md) and [0001-organization-sharing-mode](../../adr/0001-organization-sharing-mode.md)). Aggregating org-wide would let an isolated-mode User infer, through Person/Company records, that another Group has a relationship it isn't otherwise allowed to see — silently defeating the isolation an Organization deliberately chose. The accepted cost is that the same real person or company can exist as separate Person/Company records in different Groups until an Organization switches to shared mode.

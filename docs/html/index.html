01 / Project idea

撮影から名寄せまで、ひとつながりに。

BCManは単なるOCR画面ではありません。入力元の写真、そこから得た名刺、 認識結果、利用者が確定した連絡先を分けて保持し、最後に人物・会社の関係へつなぎます。 どこまでが機械の提案で、どこからが人の判断かを明確にした設計です。

1

まとめて取り込む

複数の名刺が写ったJPEG/PNGを受け付け、ローカルのOpenCV処理でカードらしい輪郭を抽出。四隅を使って台形補正します。

2

一枚ずつ確かめる

OCRと構造化の候補はそのまま登録しません。画像と14項目のフォームを見比べ、要確認項目を解消してから確定します。

3

関係として残す

確定済み連絡先から人物・会社を構成。重複らしい組み合わせだけを提示し、人が承認したときに初めて統合します。

02 / Capture to directory

利用フロー

スマートフォンで立ったまま使う場面を中心に、撮影・進捗・確認を一列につないでいます。

01

撮影・選択

登録先グループを選び、カメラまたは既存画像から写真を送信。

02

検出・補正

輪郭から複数名刺を検出し、四隅を整列して正面画像へ変換。

03

OCR・構造化

最大3枚を並行処理。文字起こし後、連絡先の各項目へ構造化。

04

確認・登録

画像をめくりながら修正。向きは90度単位で利用者が確定。

05

名鑑へ反映

人物・会社と接点履歴を作り、必要なら統合候補を後で審査。

Best effort: 8枚を品質目標とし、検出候補は安全弁として最大12枚。 個別の認識失敗は他の名刺を止めず、自動再試行後も失敗したカードは画像を見ながら手入力できます。 外形を検出できない場合は、写真全体を低信頼度の1枚として扱います。

RELATIONSHIP DIRECTORY

名刺ではなく「接点」を見る

同じ人物の複数名刺を交換日順に並べます。転職や部署変更があっても、過去の会社名と名刺所有者を各接点に残します。

人物会社接点履歴分離

メール一致、氏名＋会社名の正規化一致、会社名やWebドメイン一致から候補を作りますが、自動ではまとめません。

空白区切りAND交換日順明示の保存
RETAKE

ぼやけた1枚を撮り直す

名刺1枚だけを撮り直して画像を差し替えられます。切り出し結果を確認してから採用し、読み取りもやり直すかはその場で選びます。

05 / Domain model

3つの文脈をIDでつなぐ

責任範囲を混ぜず、認証・名刺処理・名鑑をそれぞれ独立した言葉で扱います。

Context 01

Identity

誰がログインし、どの組織・グループに属し、どこまで見えるかを決めます。

  • Organization / Sharing Mode
  • Group / User / Role
  • Session / Trusted Device / TOTP
Context 02

Business Card Management

写真から、人が確認した連絡先が生まれるまでの証拠と状態を管理します。

  • Photo → Business Card
  • Recognition Result → Contact
  • Ledger / Card Retake
  • Processing History / Audit Log
Context 03

Directory

確定済み連絡先を人物・会社へ結び、交換の履歴と統合判断を管理します。

  • Person / Company
  • Touch History
  • Merge Candidate / Split

✓PhotoとBusiness Cardは別物

Photoは撮影シーン全体、Business Cardはそこから得た一枚分の補正画像と処理状態です。原本を消しても名刺の証拠を残せます。

✓ContactとPersonは別物

Contactは一枚の名刺から確定した情報、Personは複数の確定Contactを人が統合した結果です。自動統合は行いません。

06 / Identity & privacy

個人情報を、境界の内側で扱う

Organizationを越える参照は許さず、組織内は運用に合わせて「グループ分離」か「組織共有」を選びます。

可視範囲の考え方

Organization — 厳格な境界

別Organizationの写真・名刺・人物・会社は参照不可

shared — 組織内で共有

所属Groupにかかわらず、同じOrganizationのデータを共有

isolated — Group単位

一般利用者は所属する全Groupのデータだけを参照

ID

管理者が利用者を作成

自己登録はありません。Roleは管理者 / 一般利用者の2種類です。

2F

未知の端末ではTOTP

Office Network外の未登録ブラウザは登録コードを要求。通過後は90日間Trusted Deviceとして記憶します。

8h

Cookieセッション

トークンはDBにハッシュで保持し、アイドル8時間で失効。管理者は信頼端末を即時失効できます。

5×

ログイン試行を制限

5回の失敗で15分ロック。管理者によるパスワード・TOTP再設定とロック解除に対応します。

確認前撮影原本 + 切り出した名刺画像 + 認識結果
→
確認完了後（既定）撮影原本だけを削除。名刺画像・連絡先・処理履歴は保持。原本を残す選択も可能

07 / Developer guide

ローカルで動かす

Python 3.11+、Poetry、Node.js / npmが前提です。初回は依存関係を導入し、AI APIの設定を追加します。

UIReact / TypeScript / Vite
APIFastAPI / Uvicorn
DATASQLAlchemy / SQLite
IMAGEOpenCV / Pillow
AUTHbcrypt / pyotp
TESTpytest / TypeScript build
PowerShell
# 1. AI接続を設定
cd Project/backend
Copy-Item .env.example .env
# .env の AI_API_KEY / AI_MODEL を編集

# 2. Organizationと初期管理者を作成
poetry install
poetry run python -m app.cli create-org `
  --name "会社名" --group "一般" `
  --admin-username admin --admin-name "管理者 太郎"

# 3. フロントエンドとAPIを起動
cd ..
.\start.ps1 -Install

# Frontend  http://localhost:5173/bcman/
# API       http://localhost:8000/bcman/api/health
画像入力

JPEG / PNG、1ファイル20MBまで。HEICは未対応です。

処理方式

FastAPI BackgroundTasksによる単一プロセス内の並行処理です。

永続化

既定はローカルSQLiteとファイル保存。接続先は環境変数で変更できます。

位置づけ

Dockerを使わないPoC。可用性、キュー、バックアップ等は本番化時の設計対象です。

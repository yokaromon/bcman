1. プロジェクト概要

BCMan (Business Card Management) は、写真に含まれる複数枚の名刺を自動検出し、OCRとLLMを用いて構造化データとして登録する名刺管理PoCシステムです。

1.1 核心コンセプト

  • Photo (写真): アップロードされた元画像ファイル。1枚の写真に複数枚の名刺が含まれる可能性があります。
  • Business Card (名刺): Photoから検出された個別の名刺。検出・補正・OCR処理の単位です。
  • Contact (連絡先): 名刺から抽出された構造化された情報。ユーザーが確認・修正後に確定登録されます。
  • OCR Result (OCR結果): OCRエンジンが抽出した生テキスト。検証・再処理用に保持されます。

1.2 処理フロー

写真アップロード ↓ 名刺検出 ↓ 切り抜き・補正 ↓ OCR実行 ↓ LLM構造化 ↓ ユーザー確認 ↓ DB登録

1.3 主な特徴

複数名刺対応

1枚の写真に含まれる複数枚の名刺を同時に検出・処理できます。

切り抜き（傾き補正は未実装）

検出した矩形領域を切り抜きます。斜めに撮影された名刺の透視変換による補正は現状未実装で、将来対応予定です。

OCR & LLM

OpenCVによる画像処理とLLMによる構造化JSON生成を組み合わせます。

ユーザー確認

AI結果は即時確定せず、ユーザーが確認・修正できる仕組みです。

データ保持

元画像・中間データ・OCR生テキストをすべて保持し、再処理が可能です。

権限管理

組織・グループ単位のデータ隔離と権限制御をサポートします。

3.4 ステータス一覧

写真のステータス

uploaded → detecting → detected → completed / failed

名刺のステータス

detected → corrected → ocr_processing → ocr_completed → llm_processing → review_required → confirmed

※ failed は写真（Photo）のステータスであり、現状の実装では名刺（BusinessCard）個別のステータスとしては遷移しません。

5.9 削除

DELETE /api/photos/{photo_id}
DELETE /api/cards/{card_id}
レスポンス: {"deleted": true}

物理削除。写真を消すと配下の名刺・OCR結果・Contact・処理履歴と、ストレージ上の画像ファイルがまとめて消える。確定登録済みのContactが含まれていても削除は止めない。消えた内容の要約はAuditLogに残す。閲覧できる利用者は削除もできる。

5.10 サムネイル取得

GET /api/photos/{photo_id}/thumbnail
GET /api/cards/{card_id}/thumbnail

長辺800pxのJPEGを返す。初回参照時に生成して thumb.jpg として保存し、以降はそれを返す。Cache-Control: private, max-age=604800。元画像が無い古いデータでは404。

6.3 主要処理フロー

写真処理 (services.py)

  1. detect_cards(): OpenCVでCanny Edge + Contours検出
  2. 面積・縦横比で名刺候補をフィルタリング
  3. 候補を写真上の配置順（上の行から、行内は左から）に並べ替え（ADR 0003参照）
  4. 各候補を切り抜き、detected.jpg / corrected.jpg に保存
  5. run_ocr(): 画像をBase64エンコードしてOCR APIに送信
  6. structure(): OCR結果をLLMに渡し、JSON構造化

ストレージ構成

storage/photos/{photo_id}/ ├── original.jpg # 原本（PNGなら original.png） ├── thumb.jpg # 一覧用サムネイル（初回参照時に生成） └── cards/{card_id}/ ├── detected.jpg # 切り抜き ├── corrected.jpg # 補正画像（OCRの入力） └── thumb.jpg # 一覧用サムネイル（初回参照時に生成）

削除 (ADR 0004参照)

  1. delete_card(): Contact / OCRResult / ProcessingHistory を消し、名刺の行と cards/{card_id}/ を消す
  2. delete_photo(): 配下の名刺すべてに上記を適用し、写真の行と photos/{photo_id}/ を消す
  3. 外部キーに CASCADE を張っていないため、子から順に明示的に消す
  4. 消す前に内容の要約を作り、AuditLog に記録してから commit する

権限判定

  • system_admin: 全データ閲覧・操作可能
  • org_admin: 自組織の全データ閲覧・操作可能
  • member: 自グループのデータのみ閲覧・操作可能。ただし所属組織の sharing_mode が shared の場合は組織全体のデータを閲覧・操作可能（ADR 0001参照）

6.4 拡張ポイント

名刺検出エンジン切り替え

services.py の detect_cards() を置き換えることで、OpenCVからYOLOなどに切り替えられます。

OCRエンジン切り替え

services.py の chat() 関数で使用するAPIエンドポイントとプロンプトを変更することで、PaddleOCRやCloud Visionに切り替えられます。

LLM構造化プロンプト

STRUCTURE_PROMPT (services.py 13行目) を編集することで、抽出項目や指示をカスタマイズできます。
